# กฎความน่าเชื่อถือ (rigor)

ทุกข้อในแผนที่ต้องตรวจย้อนได้ เอกสารนี้ใช้กับผู้ช่วยรีเสิร์ชและ Claude หลักเหมือนกัน ส่วนที่ 1 คัดกฎ 8 ข้อจากสเปกหัวข้อ 8 มาตามต้นฉบับ ส่วนที่ 2 บอกว่าแต่ละข้อเขียนลงข้อมูลอย่างไร (รูปแบบเต็มอยู่ใน map-schema.md)

สิ่งที่ถือว่าล้มเหลว แม้ระบบจะทำงานได้: สรุปผิวๆ แต่เรียกว่ารีเสิร์ชเชิงลึก (แหล่งน้อยหรือไม่มีอ้างอิง) มีข้อความที่ไม่มีแหล่งที่มา แหล่งที่ไม่ได้เปิดอ่านจริง หรือ URL ที่แต่งขึ้น

## 1. กฎ 8 ข้อ (จากสเปกหัวข้อ 8)

1. **ลำดับแหล่ง:** เอกสารทางการ สเปก หรือผู้เขียนต้นฉบับ → สื่อหรืองานวิจัยที่น่าเชื่อถือ → ชุมชนที่เป็นที่ยอมรับ เช่น บล็อกที่มีชื่อ หรือ repo ที่ยังมีคนดูแล → ฟอรัมและวิดีโอ ซึ่งใช้ดูมุมมองคนทำงานจริงได้ แต่ห้ามเป็นแหล่งเดียวของข้อเท็จจริง
2. ทุก point ต้องมีอ้างอิงอย่างน้อย 1 แหล่ง ข้อสำคัญต้องมีอย่างน้อย 2 แหล่งที่เป็นอิสระต่อกัน ถ้ามีแหล่งเดียวต้องติดป้ายว่า "แหล่งเดียว" และลดระดับความมั่นใจ ข้อสำคัญได้แก่ ข้อที่อยู่ในสรุป 1 นาที คำแนะนำ และตัวเลข
3. อ้างอิงได้เฉพาะ URL ที่เปิดอ่านจริงในการรีเสิร์ชครั้งนั้น ห้ามอ้างจากความจำ
4. บันทึกวันที่เผยแพร่ (ถ้ามี) และวันที่เข้าถึง หัวข้อที่เปลี่ยนเร็วให้ติดป้ายข้อมูลที่เก่ากว่าประมาณ 2 ปี
5. ถ้าแหล่งขัดกัน ให้แสดงทั้งสองฝั่งพร้อมอ้างอิงใน `conflicts`
6. แยกป้ายข้อเท็จจริง ความเห็น และค่าประมาณ
7. **ระดับความมั่นใจ:**
   - สูง: แหล่งแข็งแรงอย่างน้อย 2 แหล่งเห็นตรงกัน
   - กลาง: แหล่งแข็งแรง 1 แหล่ง หรือแหล่งอ่อนหลายแหล่ง
   - ต่ำ: แหล่งอ่อน หรือแหล่งขัดกัน
   - ทุกระดับต้องมีเหตุผลกำกับ
8. เรื่องที่ยังสรุปไม่ได้ให้ใส่ไว้ในกลุ่ม "คำถามที่ยังเปิดอยู่"

## 2. เขียนแต่ละข้อลงข้อมูลอย่างไร

### ข้อ 1: ชนิดของแหล่ง (`type`)

| `type` | คืออะไร | ความแข็งแรง | ตัวอย่าง |
|---|---|---|---|
| `official` | เอกสาร สเปก หรือหน้าที่เจ้าของเรื่องเผยแพร่เอง | แข็งแรง (ชั้น 1) | docs ของเครื่องมือ หน้าองค์กรมาตรฐาน README ของโปรเจกต์ หน้ากติกาของรางวัลที่ผู้จัดเขียนเอง |
| `primary` | ผู้เขียนหรือเจ้าของข้อมูลต้นฉบับ ไม่ใช่คนอื่นเล่าต่อ | แข็งแรง (ชั้น 1) | งานวิจัยต้นฉบับ ข้อมูลดิบ ประกาศ บล็อกของผู้สร้างที่เล่าเรื่องของตัวเอง |
| `secondary` | สื่อหรืองานวิจัยที่น่าเชื่อถือ ซึ่งอธิบายหรือรวบรวมจากต้นทาง | แข็งแรง (ชั้น 2) | บทความสื่อที่มีกองบรรณาธิการ งานวิจัยทบทวน เอกสารอ้างอิงที่ชุมชนช่วยกันเขียนอย่าง MDN ตารางข้อมูลอย่าง caniuse |
| `community` | ชุมชนที่เป็นที่ยอมรับ และฟอรัม | อ่อน (ชั้น 3–4) | บล็อกที่มีชื่อ repo ที่ยังมีคนดูแล กระทู้ในฟอรัม Stack Overflow |
| `video` | วิดีโอและพอดแคสต์ | อ่อน (ชั้น 4) | YouTube คลิปบรรยายที่บันทึกไว้ |

นิยามที่แผนที่นี้ใช้: "แหล่งแข็งแรง" คือ `official`, `primary` และ `secondary` ที่มีกองบรรณาธิการหรือผู้เขียนที่ตรวจสอบได้ "แหล่งอ่อน" คือ `community`, `video` และ `secondary` ที่ไม่ระบุผู้เขียนหรือที่มา (เนื้อหาโฆษณา บล็อกที่ทำมาเพื่ออันดับค้นหา)

ค้นและเปิดอ่านจากชั้น 1 ก่อนเสมอ ใช้ชั้น 3–4 เพื่อดูมุมมองคนทำงานจริง point ชนิด `fact` ห้ามอ้างแต่ `community` หรือ `video` ถ้าไม่มีแหล่งแข็งแรงยืนยัน ให้ตั้งเป็น `opinion` หรือไม่เขียน

### ข้อ 2: อ้างอิงขั้นต่ำ (`cites`, `key`, `singleSource`)

- ทุก `points`, `conflicts` และ `counterpoints` ต้องมี `cites` อย่างน้อย 1 id ที่ชี้แหล่งจริงใน `sources` (validator ตรวจ)
- **ข้อสำคัญ** ให้ติด `key: true` ได้แก่ point ที่ (ก) มีตัวเลขที่ผู้อ่านจะเอาไปใช้ เช่น ราคา ขนาด เวลา สัดส่วน เกณฑ์ (ข) เป็นคำแนะนำว่าควรทำหรือไม่ควรทำอะไร หรือ (ค) เป็น 1–2 ข้อที่สำคัญที่สุดของโหนด ซึ่งคุณจะบอกผู้เริ่มต้นถ้ามีเวลาแค่ 1 นาที (ข้อที่น่าจะเข้าสรุป 1 นาที) ติดเฉพาะที่เข้าเกณฑ์จริง ไม่ติดทุกข้อ
- `key: true` ต้องมี `cites` ต่างกันอย่างน้อย 2 id หรือ `singleSource: true` (validator ตรวจ แต่นับแค่ id ที่ต่างกัน ไม่รู้ว่าแหล่งอิสระจริงหรือไม่)
- **แหล่งอิสระ** คือคนละผู้เผยแพร่ คนละผู้เขียน และไม่ได้อ้างหรือคัดลอกกัน สองหน้าของเว็บเดียวกัน เอกสารกับสำเนา ข่าวประชาสัมพันธ์กับข่าวที่เขียนซ้ำ สองบทความที่อ้างงานวิจัยชิ้นเดียวกัน และตัวเลขที่เว็บหนึ่งเอามาจากอีกเว็บ (เช่น caniuse ใช้สถิติของ StatCounter) นับเป็นแหล่งเดียว
- ถ้าหาแหล่งที่สองแล้วไม่เจอ หรือแหล่งนั้นเป็นเจ้าของข้อมูลเองและไม่มีใครเทียบได้ (เช่น กติกาของรางวัลที่ผู้จัดเขียนเอง) ให้ใส่ `singleSource: true` ลดความมั่นใจลง (ไม่สูงกว่า `medium`) และบอกเหตุผลใน `confidenceReason` ห้ามเอาแหล่งซ้ำหรือไม่อิสระมาใส่ให้ครบสองแหล่ง
- สรุป 1 นาที (`summary.findings`) ใช้กฎเดียวกัน ข้อที่ไม่ผ่าน `synthesize` จะปฏิเสธ

### ข้อ 3: เปิดอ่านจริง

- "เปิดอ่าน" คืออ่านเนื้อหาของหน้านั้นจริงด้วย WebFetch, คำสั่ง `read` ของ agent-reach ตามกฎข้อ 11 ของ subagent-brief.md หรือเบราว์เซอร์ในแอป ไม่ใช่เห็นแค่ชื่อเรื่องหรือข้อความตัวอย่างในผลค้นหา
- URL คัดลอกตามที่เปิดอ่านจริง เป็นหน้าที่มีข้อความนั้น ไม่ใช่หน้าแรกของเว็บ ตัดพารามิเตอร์ติดตาม (`utm_*`) ได้ถ้ายังเปิดหน้าเดิม ห้ามแก้ เดา หรือเติมเส้นทางเอง
- เปิดไม่ได้ (404 ถูกบล็อก ต้องล็อกอิน) ห้ามอ้าง ให้หาแหล่งอื่น หรือถือว่ายังสรุปไม่ได้ (ข้อ 8)
- ห้ามอ้างจากความจำ ทั้ง URL และเนื้อหา แม้จำได้ว่าเว็บนั้นเขียนไว้ ก็ต้องเปิดอ่านอีกครั้งในการรีเสิร์ชครั้งนี้
- `accessedAt` คือวันที่เปิดอ่านจริงครั้งนั้น
- validator ไม่รู้ว่า URL มีจริงหรือไม่ ตอนตรวจสุดท้าย `check-urls` จะเรียกทุกแหล่งและจับ URL ที่ตายได้ แต่จับ URL ที่เปิดได้แต่ไม่มีข้อความนั้นไม่ได้ ความรับผิดชอบเรื่องนี้จึงอยู่ที่คนเขียน

### ข้อ 4: วันที่และความเก่า (`publishedAt`, `accessedAt`)

- บันทึก `accessedAt` เสมอ เป็นวันที่เปิดอ่านจริง รูป `YYYY-MM-DD`
- บันทึก `publishedAt` ทุกครั้งที่หน้าแสดงวันที่ ใช้วันที่เผยแพร่ ถ้าไม่มีให้ใช้วันที่แก้ไขล่าสุดที่หน้าแสดง (เช่น "last modified" ของ MDN) ถ้าหน้าแสดงแค่เดือนกับปีให้เขียน `YYYY-MM` และถ้าแสดงแค่ปีให้เขียน `YYYY` ห้ามเติมวันเอง หน้าที่ไม่แสดงวันที่เลยไม่ต้องใส่ `publishedAt` ห้ามเดา และห้ามใช้วันที่ที่เครื่องมือบอกโดยหน้าเพจไม่ได้เขียน (ช่อง `published_at` ใน JSON ของ `agent-reach` บางครั้งเป็นวันที่จากเซิร์ฟเวอร์ ไม่ใช่วันเผยแพร่)
- หน้าแผนที่ติดป้าย "เก่ากว่า 2 ปี" ให้แหล่งเอง เมื่อ `publishedAt` เก่ากว่า `accessedAt` เกิน 2 ปี ในข้อมูลไม่มีช่องสำหรับป้ายนี้ ป้ายจึงทำงานได้เฉพาะแหล่งที่บันทึก `publishedAt` ไว้
- หัวข้อที่เปลี่ยนเร็ว (ซอฟต์แวร์ เฟรมเวิร์ก AI ราคา กฎหมาย แนวทางการแพทย์) ให้ใช้แหล่งที่เผยแพร่ภายใน 2 ปีล่าสุดก่อน ถ้า point ใดอิงแหล่งที่เก่ากว่านั้น ให้บอกไว้ใน point เอง (เช่น "ตามกระทู้ปี 2018") หรือใน `confidenceReason` และลดระดับความมั่นใจ หัวข้อที่เปลี่ยนช้า (หลักการพื้นฐาน ตำราคลาสสิก) ใช้แหล่งเก่าได้ แต่ต้องบันทึกวันที่ไว้

### ข้อ 5: แหล่งขัดกัน (`conflicts`)

- เขียนหนึ่งข้อต่อหนึ่งประเด็นที่ขัดกัน `text` บอกทั้งสองฝั่งชัดเจน ("แหล่ง A ระบุว่า … แต่แหล่ง B ระบุว่า …") และ `cites` มีแหล่งของทุกฝั่ง (อย่างน้อย 2)
- ห้ามเลือกข้างเงียบๆ ถ้าตัดสินได้ว่าฝั่งไหนแข็งแรงกว่าหรือใหม่กว่า ให้ใส่ฝั่งนั้นใน `points` และบอกเหตุผลใน `confidenceReason` ถ้าตัดสินไม่ได้ ให้ใส่ทั้งสองฝั่งใน `conflicts` ไม่ใส่ฝั่งใดเป็น `fact` ใน `points` ตั้งความมั่นใจเป็น `low` และนับเป็นเรื่องที่ยังสรุปไม่ได้ (ข้อ 8)
- ต้องขัดกันจริง ตัวเลขต่างกันเพราะคนละนิยาม คนละปี หรือคนละหน่วย ไม่ใช่ความขัดกัน ให้อธิบายความต่างนั้นใน point
- `conflicts` คือแหล่งขัดกันเรื่องข้อเท็จจริงเดียวกัน ส่วน `counterpoints` คือข้อโต้แย้งและข้อจำกัดต่อสิ่งที่โหนดแนะนำหรือบอก

```jsonc
"conflicts": [
  {
    // ทั้งสองฝั่งอยู่ใน text เดียว และ cites มีแหล่งของทั้งสองฝั่ง
    "text": "เอกสารทางการของ A ระบุว่าขั้นตอนนี้ใช้เวลา 30 วินาที แต่บทความของ B ที่ทดสอบเองวัดได้ราว 45 วินาที เอกสารของ A เขียนก่อนเวอร์ชัน 3 ออก",
    "cites": ["s1", "s4"]
  }
]
```

### ข้อ 6: ป้ายชนิดของ point (`type`)

| `type` | ใช้กับ |
|---|---|
| `fact` | ข้อความที่แหล่งระบุเป็นข้อเท็จจริงที่ตรวจสอบได้ เช่น สเปก พฤติกรรมตามเอกสาร ตัวเลขที่วัดหรือประกาศ |
| `opinion` | การประเมิน ความชอบ คำแนะนำ หรือประสบการณ์ส่วนตัวของผู้เขียนแหล่งนั้น เช่น "ควรใช้ A" ในกระทู้ ข้อความจากฟอรัมและวิดีโอเป็น `opinion` เว้นแต่มีแหล่งแข็งแรงยืนยัน |
| `estimate` | ตัวเลขหรือช่วงที่ไม่แน่นอน เช่น ส่วนแบ่งตลาด ผลที่คาด ต้นทุน เวลา การพยากรณ์ รวมถึงตัวเลขที่คุณคำนวณเองจากแหล่ง เขียนฐานหรือช่วงกำกับ เช่น "ราว 30–50%" |

ไม่แน่ใจว่า `fact` หรือ `opinion` ให้ใช้ `opinion` ห้ามเขียนค่าประมาณเป็น `fact`

### ข้อ 7: ความมั่นใจ (`confidence`, `confidenceReason`)

| ระดับ | `confidence` | เมื่อไร |
|---|---|---|
| สูง | `high` | แหล่งแข็งแรงอย่างน้อย 2 แหล่งที่เป็นอิสระเห็นตรงกัน |
| กลาง | `medium` | แหล่งแข็งแรง 1 แหล่ง (รวมกรณี `singleSource`) หรือแหล่งอ่อนหลายแหล่ง |
| ต่ำ | `low` | แหล่งอ่อน หรือแหล่งขัดกัน |

- ความมั่นใจเป็นของทั้งโหนด ใช้ระดับของข้อสำคัญ (`key`) ที่อ่อนที่สุดตามตาราง ถ้าโหนดไม่มีข้อสำคัญ ให้ดูจาก points ทั้งหมด ถ้ามี point ใดอิงแหล่งที่เก่ากว่า 2 ปีในหัวข้อที่เปลี่ยนเร็ว (ข้อ 4) ให้ลดลงอีกหนึ่งขั้น แต่ไม่ต่ำกว่า `low` ส่วน point ที่อ่อนแต่ไม่ใช่ข้อสำคัญและไม่เก่า (เช่น ความเห็นจากฟอรัมที่ติดป้าย `opinion` แล้ว) ไม่ต้องลดระดับ แต่ให้พูดถึงใน `confidenceReason` ถ้าข้อที่อ่อนลากโหนดที่แข็งแรงลง ให้แยกข้อนั้นไปเป็นโหนดของมันเอง
- `confidenceReason` ต้องเจาะจง บอกจำนวนและชนิดของแหล่ง ว่าเห็นตรงหรือขัดกัน และข้อจำกัด (แหล่งเดียว เก่า ไม่มีวันที่) validator ตรวจแค่ว่าไม่ว่าง ผู้เขียนต้องทำให้มีความหมาย
- โหนดที่มี `points` ต้องมีทั้งสองช่อง ขาดอย่างใดอย่างหนึ่ง `merge` ไม่ผ่าน (ใช้กับ `self` ที่ใส่ `points` ด้วย)
- รูปแบบเหตุผล: "<ระดับ> เพราะ <แหล่งกี่แห่ง ชนิดอะไร เห็นตรงหรือขัดกัน> <ตัวถ่วง>"

### ข้อ 8: เรื่องที่ยังสรุปไม่ได้

อย่าเดาให้ครบ ถ้าสรุปไม่ได้ (หาแหล่งแข็งแรงไม่เจอ แหล่งขัดกันจนตัดสินไม่ได้ เปิดแหล่งไม่ได้) ให้ทำสองอย่าง:

1. ในโหนดของตัวเอง เขียนเท่าที่ยืนยันได้ ตั้ง `confidence` เป็น `low` และให้ `confidenceReason` ขึ้นต้นว่า "ยังสรุปไม่ได้:" ตามด้วยสาเหตุ
2. ใส่เป็น item ในกลุ่ม "คำถามที่ยังเปิดอยู่" (ค่าเริ่มต้น `g-next-4`) โดย `title` เป็นคำถาม และ `summary` บอกว่ารู้อะไรแล้วและติดตรงไหน ถ้าใส่ `points` ก็ต้องมีแหล่งตามปกติ ผู้ช่วยรีเสิร์ชทำข้อนี้ผ่านบล็อกกลุ่มพิเศษที่ Claude หลักเพิ่มให้ (subagent-brief.md)

## 3. ค้นข้อโต้แย้งโดยตั้งใจ

ทุกคำแนะนำหลักและเครื่องมือหลักต้องมีการค้นคำวิจารณ์และข้อจำกัดโดยตั้งใจ แล้วเก็บไว้ใน `counterpoints` ของโหนดนั้น

- ค้นอย่างน้อย 2 คำค้นต่อหนึ่งเรื่อง เช่น "<X> problems", "<X> limitations", "<X> criticism", "why not <X>", "<X> alternatives", "ข้อเสีย <X>", "ปัญหาของ <X>" แล้วเปิดอ่านแหล่งที่วิจารณ์จริง
- แต่ละข้อใน `counterpoints` ต้องมีแหล่งตามกฎเดียวกับ point ไม่มี `type` ให้เขียนให้ชัดว่าใครพูด เช่น "ผู้ร่วมกระทู้แย้งว่า …" "บทความของ X วิจารณ์ว่า …" และบอกเงื่อนไขที่ข้อโต้แย้งใช้ได้
- ห้ามแต่งข้อโต้แย้งให้ครบ และห้ามยกความเห็นของคนส่วนน้อยในฟอรัมเป็นความเห็นของทั้งวงการ ถ้าค้นแล้วไม่เจอข้อโต้แย้งที่น่าเชื่อถือ ให้บอกตรงๆ ใน `confidenceReason` ว่าค้นกี่คำค้นแล้วไม่พบ ห้ามเขียนข้อโต้แย้งลอยๆ

## 4. ข้อความที่ไม่ใช่ claim

`summary`, `why`, `forYou` และชื่อโหนดไม่มีช่อง `cites` จึงห้ามใช้แอบใส่ข้อเท็จจริง

- `summary` และ `why` สรุปเฉพาะสิ่งที่อยู่ใน `points` และ `counterpoints` ของโหนดนั้น (หรือของลูก) ห้ามเพิ่มข้อเท็จจริง ตัวเลข หรือชื่อที่ไม่มีใน claim
- `forYou` เป็นคำแนะนำจึงเป็น "ข้อสำคัญ" ต้องอิงจาก point ที่มีแหล่งแล้วและผูกกับ brief ของผู้ใช้ ห้ามเพิ่มข้อเท็จจริงใหม่

## 5. สิ่งที่สคริปต์จับให้ และสิ่งที่ต้องตรวจเอง

| `merge` และ `validate` จับให้ | ต้องตรวจเอง |
|---|---|
| point ไม่มี `cites`, cite ชี้แหล่งที่ไม่มี, `type` ผิด, `key` ที่ไม่มี 2 id หรือ `singleSource`, โหนดที่มี point แต่ไม่มี `confidence` หรือ `confidenceReason`, URL ที่ไม่ขึ้นต้น http(s), ไม่มี `accessedAt` | แหล่งอิสระกันจริงหรือไม่ ชนิดของแหล่งถูกหรือไม่ เปิดอ่านจริงหรือไม่ (URL ที่แต่งขึ้นแต่รูปถูกผ่านได้ `check-urls` จับได้แค่ URL ที่ตาย) ข้อความตรงกับแหล่งหรือไม่ วันที่ถูกหรือไม่ ความมั่นใจสมเหตุสมผลหรือไม่ และค้นข้อโต้แย้งแล้วหรือยัง |

ความผิดที่เจอบ่อย:

| ผิด | ถูก |
|---|---|
| ใส่ `cites: ["s1", "s1"]` ให้ดูเหมือนสองแหล่ง | ใส่ `singleSource: true` และลดความมั่นใจ |
| อ้าง URL ที่เห็นในผลค้นหาโดยไม่เปิดอ่าน | เปิดอ่านก่อน แล้วค่อยอ้าง |
| ใส่ `publishedAt` ตามที่เครื่องมือบอกโดยไม่ดูหน้า | ดูวันที่ในหน้าเอง ไม่เห็นก็ไม่ใส่ |
| เขียนค่าประมาณเป็น `fact` | ใช้ `estimate` พร้อมช่วงหรือฐาน |
| `confidenceReason` ว่า "น่าเชื่อถือ" | "สูง เพราะ Khronos (`official`) กับ MDN (`secondary`) ตรงกัน และเปิดอ่านทั้งสองเมื่อ 2 พ.ย. 2026" |
| เลือกฝั่งที่ชอบเงียบๆ เมื่อแหล่งขัดกัน | ใส่ทั้งสองฝั่งใน `conflicts` และบอกเหตุผลที่เลือก |
